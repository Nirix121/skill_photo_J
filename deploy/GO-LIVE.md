# PALMIRA: запуск на постоянном домене

## Состояние до покупки домена

- Приложение работает на `127.0.0.1:3000` от пользователя `server`.
- Веб-служба systemd подготовлена в `deploy/palmira-certificates.service`, но её нужно установить с sudo.
- Ежедневная локальная копия настроена в cron, хранится 30 последних копий.
- 10 записей `QA26092701`–`QA26092710` нужно удалить **перед запуском**, после финальной проверки. Реальные записи не трогать.
- Для сайта нужен именованный Cloudflare Tunnel; временный адрес нельзя печатать в новых сертификатах.

## 1. Включить автозапуск приложения

В SSH-терминале пользователя `server`:

```bash
cd /home/server/certificate
sudo install -m 0644 deploy/palmira-certificates.service /etc/systemd/system/palmira-certificates.service
sudo systemctl daemon-reload
sudo systemctl enable palmira-certificates
old_pid=$(ss -ltnp | sed -n 's/.*127\.0\.0\.1:3000.*pid=\([0-9]*\).*/\1/p' | head -n 1)
if [ -n "$old_pid" ]; then kill -TERM "$old_pid"; sleep 2; fi
sudo systemctl start palmira-certificates
sudo systemctl --no-pager --full status palmira-certificates
curl -fsS http://127.0.0.1:3000/health
```

Пароль sudo вводить только в терминале, не в переписке. Если служба не поднялась,
смотреть `sudo journalctl -u palmira-certificates -n 80 --no-pager`.

## 2. Подключить постоянный домен

1. Купить домен и подключить его к аккаунту Cloudflare DNS.
2. Создать **именованный** Cloudflare Tunnel и опубликовать выбранный hostname
   (например, основной домен) на `http://127.0.0.1:3000`.
3. Установить `cloudflared` как службу systemd по инструкции Cloudflare, используя
   токен именованного туннеля. Токен не записывать в этот репозиторий и не присылать в чат.
4. Установить `SITE_URL=https://выбранный-домен` в `.env` и перезапустить приложение:

   ```bash
   sudo systemctl restart palmira-certificates
   npm run rebuild-pdfs
   npm run check
   ```

5. Проверить главную, форму, страницу действующего сертификата, PDF, QR и вход в панель
   через постоянный домен. Только после этого выключить временный веб-туннель.

Выгруженные раньше PDF содержат QR и ссылки из прежнего `SITE_URL`, поэтому
`npm run rebuild-pdfs` обязателен. Если эти PDF уже переданы людям, их нужно заменить.

## 3. Перед публичным объявлением

1. Сделать `npm run backup` и сохранить копию также **вне сервера**; проверить восстановление на отдельной копии. Секретный `.env` в автоматическую копию не входит: хранить его отдельно в защищённом месте.
2. Удалить через панель ровно `QA26092701`–`QA26092710`, повторно проверить список.
3. Проверить доступность сайта после перезагрузки сервера.
4. Проверить настройки сетевого экрана и роутера: приложению не нужен входящий порт 3000;
   SSH и Cockpit оставить только там, где они нужны администратору.
5. Настроить мониторинг HTTPS-страницы и свободного места, а также получение уведомлений
   о сбоях резервного копирования.

## Параметры, которые нужно согласовать

- Точный домен и нужен ли `www` с перенаправлением.
- Куда выносить зашифрованную резервную копию и кому принадлежит хранилище.
- Должна ли главная страница индексироваться поисковиками. Сейчас на постоянном домене
  она может индексироваться, а конкретные сертификаты закрыты.
- Кто будет получать уведомления о недоступности сайта и неудачных резервных копиях.

Панель пока остаётся с входом по паролю. Cockpit используется администратором и не отключается.
